# Opening inventory in the equity fact

The current RunnerFact V1 producer adds required `trading_gate` and
`account_inventory` fields to `equity_snapshot`. This is an in-place first
production contract revision. It requires a coordinated strict consumer update;
an older parser is not a fallback. No deployment, live stream, native census
acceptance, opening release, or production readiness follows from these assets.

## Signature and identity

The signature remains `CRUCIBLE-RUNNER-FACT-BATCH-V1\0` followed by canonical JSON
of the existing closed signing header. `payload_digest` commits recursively to
canonical `facts`, including every nested inventory value. This is not the domain
event subject/raw-event-byte preimage. Changing an inventory member without
updating the facts digest invalidates the signing input.

Inventory scope repeats tenant, mode, runner, instance, spec ID/digest and
generation and must equal the signed envelope. Tenant IDs are ASCII subject tokens
of 1 to 64 bytes. Connector comes from the verified immutable deployment spec,
not a venue label or a default. Source is required but nullable: an unsupported
provider reports `status=unavailable`, `source=null`, null observation rows and a
closed reason. It does not invent a SoDEX main wallet or account ID. Observed
SoDEX account scopes and native sandbox scopes are separate closed variants.

## Evidence, values and admission

The closed model is implemented in
[`opening_inventory_contract.py`](../../src/custos/core/opening_inventory_contract.py).
Schema and shared vectors are generated by the existing RunnerFact generators.
All nested objects refuse unknown fields. Decimal wire values are canonical
strings within the unsigned 96-bit mantissa and scale-28 representation; negative
observations use a sign where the field permits it. No float, rounding, exponent
notation, signed zero or silent asset filtering is allowed. A local observation
outside the wire domain makes that entire dimension unavailable while preserving
other valid dimensions and the original risk equity. If the combined observability
batch exceeds its byte budget because of inventory, the platform outbox rolls
back that attempt and selects the complete independent risk plan, with explicit
unavailable inventory and `wire_budget_exceeded`, in the same SQLite transaction.
That plan retains the independently sampled amount, positions, nanosecond time and
event identities. It never retains a native amount while replacing only its
inventory. Rolled-back attempts consume no fact identity or sequence. Without a
trustworthy independent sample there is no risk fallback; an oversized native
batch is refused atomically. An independent batch that itself cannot fit remains
an error, rather than a fabricated value or truncated census.

Balances preserve raw asset ID/code and namespace separately from nullable
canonical denomination and mapping revision. Case conversion does not establish
asset identity. Liabilities, locked balance and collateral have distinct meaning.
An empty array denotes an observed empty result. Unknown and inapplicable results
have null rows and explicit reasons; inapplicable requires the registered source
model's guarantee. Each dimension retains its own time, height, response digest or
capture token. Separate venue reads are not a common boundary.

Completeness is independently evidenced for identity, balances, liabilities,
positions, ordinary orders, order kinds, pagination and common boundary.
`inventory_complete` additionally requires a coherent equity binding. Complete
inventory dimensions may coexist with unproven multicurrency equity: keep the
original risk amount and report `inventory_complete=false`. The supported cash
binding cannot value another nonzero denomination, an effective position or a
liability by reading only the settlement balance. Its amount, currency, time,
source identity, capture boundary and mapping must agree with the actual complete
capture and the outer equity fact. It does not introduce an exchange rate.

An existing current native cash account can also prove exact zero with no
settlement-currency row. This rule requires all eight dimensions true, the actual
no-borrowing owner guarantee, one matching current account identity, the complete
same-cut enumeration and an explicitly supported settlement denomination. Every
other observed asset must be a known mapped denomination with exact zero total;
nonzero assets, liabilities and effective positions still refuse cash coherence.
An observed empty balance list stays empty, and no synthetic zero row is added.
Unavailable or incomplete balances, absent current identity, unknown mapping,
wrong source/token/time and a nonzero claimed equity cannot use this rule.

Closed parsing is not capability authorization. `capability_binding` must match
the envelope's capability ID/version/digest, and the registered manifest must
actually support its schema, source model and capture API. Coherent or complete
observations also require that manifest's complete model, mapping and runtime
artifact. `require_opening_inventory_support` is the separate admission check for
the actual manifest. The current capability declares conservative SoDEX reads and
unavailable observations; `complete_models`, mappings and complete runtime
artifacts are empty. A future-shaped native parser fixture does not authorize
`sandbox-account-state-v1` merely by naming it.

The native source variant retains the actual `incarnation`, client/account/venue,
`account_type`, API/model revisions, runtime version, opaque `configuration_json`
and the SHA-256 of its original UTF-8 bytes. Configuration is not reparsed and
reserialized to produce that digest. The API is `execution-account-capture-v1`
and the observation model is `sandbox-account-state-v1`. Native account types
`CASH`, `MARGIN`, `BETTING` and `WALLET` retain their own meaning; only `CASH` with
the actual owner's `no_borrowing_model=true` may mark liabilities inapplicable.
Atomic margin observations do not prove no liabilities or cash valuation.

`native_capture` is required and nullable. SoDEX and unavailable observations carry
null. An observed sandbox source requires the closed descriptor containing the
actual node UUID, `environment=SANDBOX`, positive capture sequence, integer u64
`observed_at_ns`, no-borrowing flag and all nine actual owner frontier channels.
Those channels are time events, system events/commands, execution events/commands,
data events/commands, external events and maintenance; the canonical wire names
and order are generated by the schema. Each admitted count equals its applied
count. The integer nanosecond time converts to UTC without a float conversion of
the epoch value. Every applicable observation must use that exact time and the
recomputed SHA-256 token over canonical JSON `{"source":scope.source,
"native_capture":native_capture}`. This descriptor binds a reported boundary;
it does not replace registered runtime capability evidence or prove a native API
was called. The host now acquires a native capture handle before its hosted run,
but acceptance of a fixed installed runtime artifact remains a separate gate.

Native balances retain precision, currency type and ISO code in required-nullable
`native_currency`; SoDEX carries null. `native_currency_codes_v1` identifies exact
native definitions for USD (2/FIAT/840) and USDT, USDC, BTC, ETH (8/CRYPTO/0).
A coincident asset code with different metadata is not that denomination; virtual
or other currencies remain unmapped until their own explicit mapping exists.
Native positions preserve settlement currency and a null average entry price
because that API deliberately provides no exact average. Native orders preserve
client and nullable venue identity, nullable price/trigger price, pending state
and matching-engine membership. They are not fabricated as zero-priced orders.
Each dimension permits at most 192 rows; an over-budget dimension becomes unknown
as a whole rather than silently dropping rows. The aggregate outbox byte fallback
still protects the independent risk facts when their combination is larger.

The consumer handoff therefore requires all of these checks:

1. Keep the existing canonical digest/header signature verification.
2. Strictly decode the closed inventory and required-nullable fields; compare
   scope/capability identity, canonical values and the equity binding to the batch.
3. Resolve the registered manifest by the signed digest and execute its actual
   schema/model/API/mapping/runtime support checks. A matching digest alone is
   insufficient. Decode-legal but unsupported native vectors fail at admission.
4. Compare source account/configuration with the authoritative deployment spec.
   Recompute completeness, cash equity and opening eligibility. An observed extra
   asset, position or order cannot be dropped to make opening eligible.
5. Preserve valid risk equity with unavailable or unproven inventory in the
   transactional inbox and projection. It must not advance opening or NAV release.

Shared vectors have only been executed on the producer until the consumer owner
records its own strict decode, admission and real PostgreSQL results. Historical
producer/consumer receipts retain their original revision and bytes; they do not
certify the current revision. The current asset index explicitly marks consumer readiness false and lists
current-revision consumer, native inventory and release/fence blockers. Current
consumer and runtime acceptance remain open.

## Risk cadence and lifecycle

The canonical host records an independent risk sample with its own amount,
positions, nanosecond observation time, source and sample identity. It also tries
the native owner capture when the portfolio sample fails. A typed opening bundle
retains these independent sources, including explicit risk unavailability. Only
a complete, coherent, manifest-admitted no-borrow cash capture can supply native
equity and empty effective positions at the capture's exact nanosecond time. A
nonempty native order list, unknown denomination, nonzero other asset, effective
position or liability prevents that cash qualification; the original rows remain
observed and unproven. Native sample identities use the full capture token, so two
captures at the same timestamp retain distinct identities.

The bundle, independent positions and complete primary/fallback plans retain
immutable canonical JSON bytes. Construction inputs and later property reads do
not share mutable nested dictionaries with the signing plan. The admitted native
sample also binds the exact inventory snapshot, including artifact admission.
Heartbeat keeps its own local observation time. Capital telemetry uses the
independent portfolio equity and records that sample's source, time and identity;
its log time remains the actual capital-sample completion time. If independent
risk is unavailable the auxiliary capital log is omitted, even when a native risk
sample is usable. Health/status and readiness reads can also fail independently;
those failures produce a degraded heartbeat and still attempt the native bundle.
Source retirement and task cancellation continue to abort the old observation.
An opening provider, transport or conversion failure produces
unavailable inventory rather than suppressing trustworthy equity and positions. A paused but still current source
may report risk; it has no permission to send orders. Stopped, archived,
superseded or locally retired observations must not be signed for the old source.

Venue census runs in one bounded background slot per host. Each risk tick consumes
a completed observation or immediately reports unavailable. It never awaits four
15-second REST reads. Repeated ticks do not create more workers. Stop/replacement
retires the result without cancelling a `to_thread` wrapper and freeing its slot
while the worker is still alive. A late result retains its original source times
and cannot be made coherent by giving it the latest risk timestamp. The separate
explicit diagnostic read retains its waiting semantics.

The production loop compares host observation tokens before and after sampling.
A platform token always contains the exact durable command fingerprint. The
platform observability outbox rechecks signed desired scope, connector and
running/paused state within its `BEGIN IMMEDIATE` before allocating sequence or
signing. This closes the asynchronous gap between the last host read and signing.
It does not add a platform process fence or an opening API. The existing explicit
simulation host has a separate token variant and can emit only unavailable,
awaiting-release equity; a platform token missing a fingerprint cannot select it.

The gate remains default closed. The current installed `sodex.3` runtime has no
capture API and remains explicitly unavailable. The native API's crate version is
not a wheel identity. A future-shaped handle or artifact fixture proves conversion
semantics only. Fixed CPython 3.12 artifact installation, verified artifact identity,
registered capability and actual host-to-signed-outbox consumer acceptance remain
necessary before claiming native runtime completion. Reliable platform process fencing, independent signed release, atomic release
acknowledgement and first-fill ordering require their own implementation and
acceptance. Ordinary cache contents, initial balance maps and empty reports are
not a complete native or venue account census.
