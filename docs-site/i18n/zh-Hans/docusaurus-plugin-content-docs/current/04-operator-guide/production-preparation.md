live 使用 ARX 签名部署，离线输入不能授权实盘。每个交易所、每种产品分别完成验收，现货结果不能代替永续结果。

## 准备主机

使用支持 `amd64` 或 `arm64` 运行镜像的 Linux 主机，记录 Ubuntu 版本、架构、运维责任人和恢复访问方式。同步系统时间，配置交易所及 TLS 控制面所需的网络访问，为加密金库、事实发件箱和执行状态提供持久存储。信任材料以只读方式挂载，并核实容器用户对受保护文件的访问权限。

安装本次验收选定的精确镜像并验证发布签名。完成 runner 注册，在本地配置交易所密钥，核实交易所侧已禁用提现。先验证测试网部署、成交、撤单、重连、进程重启和账户核对，再申请实盘批准。

## 运行环境批准

签名 daemon 要求同时提供以下输入：

| 输入 | 用途 |
|---|---|
| `--runtime-promotion-receipt` | 选定运行版本的签名批准文件 |
| `--runtime-promotion-bundle` | 该文件的签名及验证材料 |
| `--runtime-sigstore-trusted-root` | 运维方配置的可信验证根 |
| `--runtime-image-digest` | 部署配置选定的精确镜像摘要 |
| `--runtime-source-revision` | 镜像记录的源码版本 |

不提供批准材料时，live 保持关闭。输入不全、文件被修改、签名方不符合要求或镜像与源码版本不匹配，都会导致启动失败。使用发布方提供的验证根，不能让待验证文件自行指定信任来源。

仅在准备好的签名配置中选择 `--enabled-mode live`。该参数用于选择传输会话，不会跳过批准验证。每次部署仍须通过签名晋升证据、策略产物和有效风险策略检查。运行环境批准也不代表整个生产系统已经通过验收。

## 交易所输入

[SoDEX](/engines/sodex) 要求明确的钱包、账户和结算币种。[OKX](/engines/okx) 要求 API passphrase、区域和账户设置。永续配置当前覆盖线性合约。验收账户应与手工交易及其他策略隔离，确保账户级证据能核对到本次部署。


现货基础资产须能由签名金额契约表示。当前币种代码为 `USD`、`USDT`、`USDC`、`BTC`、`ETH`、`VUSDC`、`VBTC` 和 `VETH`，带 v 前缀的资产保留独立身份。不支持的现货资产在节点构建前即被拒绝；线性永续的基础资产符号本身不代表保证金币种。

## 首次实盘验收

记录批准的账户、交易对、策略参数、单笔及总名义金额上限、亏损阈值和停止步骤。首轮按这些明确限制运行，通过 ARX 核对交易所订单、签名成交、手续费、余额和持仓，并测试撤单、断线和进程重启。健康探针或配置构建成功不能代替这些验收。

新构建镜像不能沿用 sandbox 或旧版本验收结论。账户证据缺失、历史查询截断或结算单位不一致时，核对保持未完成。清算、自动减仓和额外 builder 费用须有明确核对支持，相关结果才能通过验收。
